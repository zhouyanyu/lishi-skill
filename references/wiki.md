# Wiki 建档、续接与校验

## 文件结构

沿用用户已有位置和结构；新档案可采用：

```text
书名-版本/
├─ 首页.md
├─ 来源与进度.md
├─ 原文/
├─ 篇卷笔记/
├─ 大事记.md
├─ 阶段总览/
├─ 事件/
├─ 人物/
├─ 政权与群体/
├─ 地理/
├─ 制度/
├─ 文化/
└─ 争议与待查证.md
```

仅建立当前有实质内容的目录／专题。首页与来源进度首批创建并有真实内容，链接只指向现存文件；待处理篇卷使用无链接文字。多书默认分别保存原文与篇卷笔记；用户要求合并知识库时共用主题页，并保留书籍版本和来源编号。

页名保留原篇名并处理文件系统非法字符，加稳定排序编号；篇卷 ID 在来源进度中登记。人物、事件和术语先查已有索引及别名，再决定复用或建页。小条目可汇入索引条目，不因想让姓名可点击而创建空页。重大独立主题页有实质内容和反向来源链接。

## 分批工作

1. 读首页、进度和有关主题页，确认版本、已有实体、段号规则与用户偏好。
2. 按正文顺序读取实际材料，提取并核对正文和注释；建立／复用原文页与锚点。
3. 详细精读当前单元，覆盖原文段组并写篇卷笔记；登记处理范围。
4. 更新本批人物、地理、制度与文化。文化内容在每批检查，不等全书末尾才补。
5. 将事件汇入纪事本末页、记载对照与大事记，更新必要图表和阶段总览。
6. 检查关联来源、链接和覆盖状态，保存下一续接点，继续下一批。

实体别名与关系在全书后续材料中修订，重要更正同步有关图表和汇总页。保留用户批注，必要时将自动整理区与手工区分开。重复处理更新既有文件，不重复追加相同条目。不涉及改造旧档案时，不因新增一卷重写全部目录。

## 来源与进度的建议表

`单元ID｜原卷篇名｜材料类型｜来源路径／页段｜提取状态｜精读覆盖｜专题汇总状态｜待核查｜下一位置`。

正文、古注、现代注、附录分列范围；读者实际阅读进度另记，自动整理不能自动提高读者进度。暂未读过的来源列待处理，不能填“已互证”。已整理部分的总览注明覆盖范围。

## 链接约定

普通 Markdown 用相对路径、真实标题锚点；Obsidian 用路径限定双链。源段落标题如 `P0001` 的普通 Markdown 锚点为 `#p0001`。同名页面用路径消歧，禁止猜测仓库根。每个专题给相关篇卷笔记和原文依据，笔记链接专题，首页提供导航。

重提原文需维护旧锚点映射。删除或合并文件前核查入站链接、保留用户内容，先归档而非直接删除。来源改变时更新实际受影响页面，并记录重大修订。

## 交付检查

- 实际目录的请求范围都具有实质笔记；原文提取、精读、专题汇总分开计数。
- 篇卷分段信息未被宏观摘要代替；数字、制度与文化细节完整程度人工对照原文。
- 关键判断有支持它的真实段落，来源层次明确，冲突没有被抹平。
- 大事记与事件页互相连接；人物、任职、地名与制度具时间范围。
- 文化专题有实际信息，官方规定、生活实例及研究解释分开。
- 文件与锚点有效；没有用空页填补链接。图表含义、时期与出处一致。

运行只读检查脚本：

```text
python <lishi安装目录>/scripts/check_links.py <Wiki目录>
```

Obsidian 链接相对于更大仓库时加 `--vault-root <仓库根>`。脚本检查本地 Markdown 内联链接、双链、标题／区块锚点及围栏；未支持的引用式 Markdown 链接会提示人工检查。返回成功不证明史实、源段落支持关系、精读覆盖、Mermaid 语法或实际渲染，仍须上述人工核对。

长书遇到限制时保存具体续接点、未完成范围和阻碍。最终交付首页、覆盖统计、关键专题与重要待查事项，不把原文已提取数量当成已精读数量，不承诺没有设置的后台自动运行。
