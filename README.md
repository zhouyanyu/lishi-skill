# lishi：历史精读、纪事本末与文化 Wiki

lishi 是面向 Codex 等支持 `SKILL.md` 的助手的历史阅读 skill。以纪传体正史为核心，兼容学术、文化类历史著作，帮助把整本书整理成可回查、可持续维护、可提问的 Markdown 知识档案。

它保留正史的信息密度：任职、制度、数字、地理和文化细节都可进入详细笔记。大事记和简洁回顾提供导航，不取代底层精读。

## 核心设计

四层档案相互连接：

**分段原文与稳定锚点 ↔ 详细篇卷笔记 ↔ 纪事本末及文化制度专题 ↔ 大事记与阶段总览。**

| 层次 | 保存什么 | 可以回答什么 |
|---|---|---|
| 原文 | 实际正文、注释、版本及分段定位 | 这条结论依据哪段文字？ |
| 篇卷笔记 | 按原书顺序详细精读本纪、列传、志、表或学术章节 | 这一篇有哪些信息，难点在哪里？ |
| 主题 Wiki | 人物、事件、战争、地理、制度、文化及记载对照 | 这件事的前因后果是什么，各处怎么记？ |
| 导航总览 | 大事记、阶段局势、人物和主题入口 | 这一时期怎样变化，接下来从哪里读？ |

Mermaid 展示关系、事件顺序、战争阶段、机构和礼仪流程。详细来源与数据保留在文字和表格中。

## 安装

仓库根目录本身就是 skill：`SKILL.md` 不在额外子目录内。安装后的目录名称为 `lishi`，仓库名称为 `lishi-skill`。

在 PowerShell 中使用 SSH 克隆。以下示例适用于尚未安装 lishi 的情况：

```powershell
git clone git@github.com:zhouyanyu/lishi-skill.git

$lishiCodexRoot = $env:CODEX_HOME
if ([string]::IsNullOrWhiteSpace($lishiCodexRoot)) {
    $lishiCodexRoot = Join-Path $HOME '.codex'
}
$lishiSkillsRoot = Join-Path $lishiCodexRoot 'skills'
$lishiInstallPath = Join-Path $lishiSkillsRoot 'lishi'
if (Test-Path -LiteralPath $lishiInstallPath) {
    throw 'lishi 已安装，请先比较现有定制与新版本，不直接覆盖。'
}
New-Item -ItemType Directory -Path $lishiInstallPath -Force | Out-Null
Copy-Item -LiteralPath '.\lishi-skill\SKILL.md' -Destination $lishiInstallPath
foreach ($lishiResourceName in @('agents', 'references', 'scripts')) {
    Copy-Item -LiteralPath (Join-Path '.\lishi-skill' $lishiResourceName) -Destination $lishiInstallPath -Recurse
}
```

Windows 若 Git 默认 SSH 无法使用系统已加载的密钥，可以在克隆时指定系统 SSH：

```powershell
git -c 'core.sshCommand=C:/Windows/System32/OpenSSH/ssh.exe -o BatchMode=yes' clone git@github.com:zhouyanyu/lishi-skill.git
```

需要已配置的 GitHub SSH 访问权限。无需为此修改全局 Git 配置或读取私钥。安装后在助手中选择 lishi 或输入 `$lishi`；如果当前会话尚未识别新 skill，可在新会话中调用。

## 最简单的使用方式

上传一本可读取的历史书，然后输入：

```text
用 $lishi 整理这本书。
```

默认整理文件包含的全部可读正文及相关历史注释，建立完整档案。助手会确认版本、目录、范围和保存位置，内部按批次持续处理，不默认只做前几章，不逐批要求“是否继续”。

用户指定的位置和已有档案优先；否则在任务交付目录下建立 `历史Wiki/书名-版本/`，无专用交付目录则放在当前工作区。原书和笔记不放进 skill 安装目录。

只上传部分卷册，就整理全部已提供部分，并明确原书覆盖不全。只说书名不会凭空生成该版本的逐段精读。

## 整本书的详细处理流程

### 1. 识别原书与版本

读取作者／编者、版本、目录和实际正文，辨认本纪、列传、志、表、附录和注释。保留原书卷篇结构，不把 EPUB 的每个 HTML 或 PDF 的每页直接当成章节。

EPUB 按阅读顺序及实际标题解析；PDF 检查阅读顺序，扫描件按工具条件 OCR 并核对疑读、表格和数字。材料损坏或加密时记录可读范围，不凭目录编造正文。

### 2. 保存分段原文和锚点

每个实际阅读单元保存主要原文页，正文用 `P0001` 等稳定段号，注释用 `N0001` 等编号，并记录注者、引书及其与正文的关系。

段号来自实际提取，是本版定位编号，不是印刷页码。按自然段和完整语义分段，保留诗文、奏议、诏令与表格结构。建立后不因新增笔记重新编号。

原文定位示意如下，内容仅说明结构：

```markdown
# 原书篇名

来源：实际书名、版本、源文件或原锚点。

## P0001

实际提取的正文。

## N0001

标明注者和所引文献的实际注释。
```

笔记链接对应的真实段落，必要时附短摘录或检索词。不会把人名首次出现处机械当作某次事件的依据。

### 3. 逐篇卷、逐段组精读

每篇笔记先给简短概述与导航，再按原文顺序记录段落或连续段组的信息，保留可核对的覆盖范围。

| 材料 | 精读重点 |
|---|---|
| 本纪、编年史 | 纪年、诏令任免、战争外交、财政制度、灾害、礼仪及社会记录 |
| 列传 | 身份家世、生平阶段、任职迁转、行动主张、人物关系、当地制度文化及史家评价 |
| 志、制度史 | 定义、结构、运作程序、沿革、地区差异、具体数据、实例、执行问题与改革 |
| 表 | 世系、封爵、承袭、任职时序及并行关系，保留原列义、单位和缺载 |
| 学术文化著作 | 研究问题、论点、证据、论证过程、观点分歧及适用范围 |

不会把密集任命写成“调整了官员”，也不会把一卷制度志只压成几句常识。重复资料可以归纳，但保留支持段号；普通信息也留在精读层，不以是否属于“大事”决定去留。

### 4. 建立纪事本末与记载对照

同一事件散见于本纪、列传、志和表时，汇入统一事件页，按背景、触发、经过、转折、结果和后续影响组织。大事记按时间链接事件页。

记载对照列出各来源的实际说法、原文锚点和关系：互补、重复、独立佐证或冲突。不同书可能共用同一材料，不能按出现次数认定史实。

战争页进一步保留目标、参战势力、指挥、部署、行动阶段、补给交通、地形季节、兵力伤亡口径与社会后果。

### 5. 重点整理文化与制度

文化是默认核心成果。除诸志外，本纪、列传、注释中的文化材料也汇入专题：

- 礼仪、祭祀、婚丧、节令与生活习惯。
- 乐制、乐器、舞蹈、表演与艺术传播。
- 舆服、仪卫、车舆、器物、形制材料与身份限制。
- 宗教、思想、教育、艺文、知识与技术。
- 历法、天文、灾异记录及当时解释。
- 地方、阶层、职业和群体文化差异。

文化页解释“是什么、谁使用、何时何地、怎样进行、意味着什么、如何变化”。官方礼制、实际生活案例和研究解释分别记录，不能把宫廷规定当成全社会习俗。

制度页保留职责、品秩、机构隶属、选任考核、流程、沿革及实践差异。古代“选举”按选官取士理解。

### 6. 配置 Mermaid 图表

| 主题 | 常用图表 |
|---|---|
| 人物与势力 | 分时期的亲属、统属、同僚、联盟或对立关系图 |
| 大事记与阶段 | 时间线及同期事件图 |
| 战争 | 战争阶段、指挥关系、行动顺序与补给条件图 |
| 制度 | 机构层级、选任及办理流程、制度演变图 |
| 文化 | 仪式流程、分类层级与文化变迁图 |
| 学术论证 | 论点、证据和解释的关联图 |

箭头注明含义；推断与争议显式标注。按时期、势力和事件拆图，不把全书挤进一张人物巨网。复杂内容主动绘图，简单内容不强制固定图数。

战争路线图表示顺序和连接，不按真实地理比例；真实距离、方位与山川地形需要有依据的地图。图表不替代数字表和来源定位。

### 7. 更新进度与检查

持续记录可用材料、已提取原文、已精读范围、已汇总专题、待核查和下一续接位置。用户的阅读进度另记，不随自动整理推进。

检查实际篇卷覆盖、关键原文依据、链接锚点、时间范围、文化信息和图表一致性。发生执行限制时保存已完成与剩余范围，不把首批或全文提取当成全书精读完成。

## 输出目录

```text

├── 首页.md
├── 来源与进度.md
├── 原文/
├── 篇卷笔记/
├── 大事记.md
├── 阶段总览/
├── 事件/
├── 人物/
├── 政权与群体/
├── 地理/
├── 制度/
```

普通 Markdown 使用相对链接。明确使用 Obsidian 后可沿用路径限定双链；原文标题锚点保持真实存在。用户的感想和手工批注保留。

## 使用示例

### 正史整书

```text
用 $lishi 整理这本《三国志》，正文和裴松之注分别标识，
保留详细篇卷笔记，建立事件本末、人物关系、战争时间线和文化专题。
```

陈寿正文、裴松之注及注中引书区分；同一战事跨传汇总，不同记载并列保留。

### 指定文化重点

```text
用 $lishi 整理《明史》的礼志、乐志和舆服志。
重点保留仪式程序、器物形制、身份差异和制度变化，并用 Mermaid 图解。
```

### 学术著作

```text
用 $lishi 精读这本文化史著作，按章整理作者的论点、证据和论证过程，
将涉及的礼俗、物质文化和地区差异汇入专题 Wiki。
```

### 查询和互证

```text
用 $lishi 查一下：这场战争在本纪和相关列传中分别怎么记载？
有哪些互补或冲突？请链接到具体原文。
```

### 接着处理与接续阅读

```text
用 $lishi 接着整理这个已有 Wiki，按“来源与进度”继续未完成的篇卷。
```

```text
我读到这一传了。用 $lishi 帮我回顾当时的局势、相关人物和制度文化背景。
```

### 画图与保存问答

```text
用 $lishi 画出这个时期的主要人物关系，注明关系有效时间及来源。
```

```text
用 $lishi 把刚才查证的内容加入文化专题，并更新相关篇卷链接。
```

窄问题默认直接回答，不自动创建整套 Wiki。默认可以使用已核实的全书材料；需要限制后文时说明当前阅读进度。

## 证据与边界

明确区分史料记载、史家评价、研究观点和综合推断。原文中的传闻、言论、褒贬及心理解释不自动成为确定事实。

保留原纪年和数值单位，换算须有依据；古地名现代对应注明确定程度；规定与实践、不同朝代同名官职分别处理。资料缺失时写待查，不补出精确日期、兵力、关系或引文。

本项目是工作方法和模板，不附带正史全文、个人 Wiki 或现成历史数据库。它不提供一键独立运行的全书摘要程序；文件解析和实际阅读由调用 skill 的助手及其可用工具完成。扫描件 OCR、网络查证和 Mermaid 渲染取决于环境，不能仅因结构检查通过就声称史实或渲染正确。

| [链接检查脚本](scripts/check_links.py) | 本地 Markdown 链接、双链、标题／区块锚点及围栏检查 |

链接检查脚本仅依赖 Python 3 标准库。在仓库根目录执行：

```powershell
python .\scripts\check_links.py 'D:\笔记\历史Wiki\书名-版本'
```

Obsidian 链接指向更大仓库时：

```powershell
python .\scripts\check_links.py 'D:\笔记\历史Wiki\书名-版本' --vault-root 'D:\笔记'
```

这些路径是示例，替换成自己的实际位置。脚本只读，错误退出码为 1；引用式 Markdown 链接会提示人工检查。它不检验史实、段落是否支持结论、精读是否充分或 Mermaid 实际渲染。

## 后续更新与 SSH 发布

本仓库：`git@github.com:zhouyanyu/lishi-skill.git`。

维护者已要求：后续修改 lishi 时，同步更新本地安装版本、仓库和必要的 README，并在 PowerShell 中通过 SSH 上传。这是随修改执行的约定，不是定时后台同步。

正常流程：检查安装版和 checkout → 获取远端最新状态 → 修改并验证 → 审查 diff → 明确暂存发布文件 → 提交 → SSH 推送 → 对比本地和远端提交。

保留别人已有的改动，不强制推送。仅发布 skill、模板、工具及文档，原书、个人笔记和阅读进度不上传。其他使用者的定制不会自动推送给原作者；fork 的发布目标由使用者明确指定。
